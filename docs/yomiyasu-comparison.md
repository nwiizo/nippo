# yomiyasu と nippo の比較

2026-10-30に、ローカルの yomiyasu 2.5.0（commit
`29d67ccb05e370b5958d72920a9cd1aa829dee80`、未コミット差分なし）と nippo 0.1.8 の
Skill・検査コード・テストを読んで比較した。以下は静的な比較であり、同じ入力を両方の
ホストで生成した性能比較ではない。yomiyasu の検査ツールは実行していない。

## 利用者の目的と設計の違い

| 観点 | yomiyasu | nippo | nippo への反映 |
| --- | --- | --- | --- |
| 進めたいこと | 原文や資料の意味を保って日本語を推敲する | 作業履歴を整理し、報告・振り返り・次の行動選びに使う | 語句の置換より、依頼・判断・実行・完了の取り違えを防ぐ |
| 根拠 | 原文・資料と最終稿を照合する | collector JSON と生成レポートを照合する | 元の発言の条件・確度・理由の有無を保つ具体的な手順を追加 |
| 検査の役割 | lint / diff は見直す候補を出す。意味保持や読みやすさの合格とはしない | Rust のテストは収集・集計・配布を検証する。生成文の正確性は証明しない | 機械検証とSkillによる読み比べを完了報告で区別する |
| 最終稿の確認 | run の記録と最終稿のハッシュを verify で照合する | 保存後の確認が抽象的だった | 保存したファイルを読み、今回の入力と照合。変更した場合は再確認 |
| 評価資料 | 回帰テストと過去の比較例がある。比較例の冒頭で現行版の合格例ではないと明記 | collector とインストールの回帰テストが中心 | 生成時に起こる誤りの固定事例と、今後の評価条件を追加 |

## 今回直す箇所

共通の品質確認を `report-quality.md` に分け、両ホストの Skill と配布バイナリから参照する。
guide に残っていた理解度の推定・本人の判断理由の代筆・未記録の所要時間の指定を改める。
insight は複数の記録を傾向の根拠とし、未記録の感情や意図で分析の欄を埋めない。

yomiyasu の日本語規則を一式組み込むことや、毎回必ず呼び出すことはしない。nippo に必要なのは、
日報の事実を保ちながら用途に応じて整理すること。文章の推敲を追加で依頼された場合には併用できるが、
推敲後も期間・統計・判断の確度を照合する必要がある。

入力全文の永続保存やハッシュによる検査記録は今回導入していない。nippo の一時データを削除する
方針との調整が必要で、ハッシュだけでは日報の主張が履歴に支えられているか分からないため。
現状は保存した本文の読み比べであり、検査後の改変を機械的に検出する機能はない。

## 比較で分かった検証の限界

既存の Rust テストが通っても、Skillが出典を必ず付けることや、本人の理由を補作しないことまでは
確認できない。`evals/report-quality.md` の固定事例は評価の基準であり、モデル実行済みの結果ではない。
効果を比較する場合は旧版と新版で同じ入力・依頼・モデル・設定を使い、保存した出力を根拠とともに
判定する。yomiyasu の過去のスコアや例文を nippo の品質の証明に使わない。
