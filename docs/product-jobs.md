# 利用者が進めたいことから機能を選ぶ

ジョブ理論は、ある状況で人がどのような前進を求めて道具を使うかを見る考え方。
機能面だけでなく、感情面・社会面も含む。
出典: [Christensen Institute: Jobs to Be Done](https://www.christenseninstitute.org/theory/jobs-to-be-done/)（2026-10-30確認）。

以下は既存のモードと PR #41 の不具合から立てた設計上の仮説であり、利用者調査の結果ではない。
共通して目指すのは、履歴を読み返す負担を減らし、根拠を確かめて自分で判断できる状態にすること。

## 状況と必要な支援

| 状況 | 進めたいこと | 必要な支援と既存モード | 確かめる結果 |
| --- | --- | --- | --- |
| 終業時に作業を思い出せない | 今日扱ったことと自分の判断を取り戻したい | source を横断する daily / brief、本人の発言と自動通知の区別 | 通知を本人の判断として訂正する箇所がない |
| 1on1・進捗報告が近い | 状況を誇張せず伝え、必要な相談を進めたい | report、確認済み成果と未確認事項、出典、相談事項 | 相手が根拠を確認し、判断が必要な点を特定できる |
| 評価面談の準備をする | 自分の貢献を根拠付きで説明したい | review、期間内の記録と活動量の整理 | 活動量を成果や能力と取り違えず説明できる |
| 同じところで詰まる・翌朝着手しづらい | 経験から次に試すことを自分で選びたい | reflection / insight / ledger → plan、出典付きの候補と本人の記入欄 | 候補から一つ選び、最初の行動を言葉にできる |

## 0.1.8 で優先すること

1. **判断の誤帰属を防ぐ**: PR #41 の目的を採用する。自動挿入分は通常の判断抽出から外すが、診断時には `--include-prompt-noise` で確認できるよう保持する。
2. **履歴を取りこぼしにくくする**: Claude Code / Codex の保存先設定と確認できた記録形式に対応し、Codex の利用量通知の二重計上を防ぐ。
3. **報告の根拠を守る**: report / review / trend にセッション詳細を渡す。依頼・実行・完了を区別し、テンプレートでも推測による成果・進捗率・成長の補完を求めない。
4. **用途に合う手順へ導く**: Skill の呼び出し範囲を明確にし、目的から既存モードを選べるようにする。共通手順とモード別資料を分け、配布時の参照切れを検査する。

## 次に検討する機能

最優先の候補は **収集範囲と欠測の表示**。保存先不一致・読めない記録・本人の発言がない
自動実行を「作業がなかった」と誤解せず、不足を直せるようにする。現在は対象 source・期間と
制約を表示・説明できるが、欠測の件数や理由を網羅する機能はない。

次は **成果の出典と完了状態の収集**。現在の collector はプロンプトと活動の集計が中心で、
AI の回答全文や完了を裏づけるツール結果を網羅しない。外部報告での未確認事項が多い場合に、
必要な記録・機密情報の扱い・出力量を定めて追加する。現状の Skill は不足を未確認と記載する。

自動実行の成果も報告に含めたい場合は、本人の判断を拾う処理と、実行結果を拾う処理を
分ける必要がある。`--include-prompt-noise` を常用することで代替しない。
通知連携や自動タスク化、能力スコア、新モードの追加は、上の不足を解く根拠が出るまで優先しない。

0.1.8では、[出典の確認と保存した本文の読み比べ](report-quality.md) を具体化し、未確認事項を区別する。
